The current-head runtime and repaired Python SDK passed the local release checks below. Two SDK affordability gaps were fixed locally; the known pre-existing native Rust Shield limitation remains documented.

Validation target: [PR #3220](https://github.com/RaoFoundation/subtensor/pull/3220) at `85a857922f70c218d499d2485b899fa9ef261a05`, compared with main at `6a972693ae9580541225bd37696ac2fee26b8ae9`. The initial checkout was clean. The runtime and committed benchmark weights remained unchanged. The tested working tree includes two local SDK repairs. Protected pure-proxy creation now checks a distinct delegate's ability to pay transaction fees even when another account pays the reserves. Account obligations are aggregated by underlying AccountId so alternate SS58 prefixes cannot split the check. Multisig approvals now combine their immediate refundable reserve with inner and Shield carrier fees, including direct SDK approvals and nested/batched planning. Deferred execution reserves remain separate from the first approval while permanent-spend policy still applies to the authorized operation. The regression suite covers plain and Shield routes, exact balance boundaries, frozen balances, and rejection before unlocking/signing.

The complete local preflight passed, including both Clippy configurations, generated SDK/docs drift, PAPI checks, release builds and mainnet upgrade checks. Rust workspace results were **3,610 passed, 0 failed, 47 explicitly ignored**; none of the ignored tests were ML-DSA or hashed-account tests. The full offline SDK run passed **3,880 tests with no skips**. The configured SDK typecheck exited successfully with 250 nonfatal diagnostics. The gate used the pinned try-runtime binary through a temporary exact-byte Wasm copy because its path parser lowercases `Desktop`; no checks were removed. Both earlier gate failures and the successful run are retained.

All **119 unique live pytest cases passed, with no skipped or unresolved cases**. The table below records the completed operation matrix. Additional RPC, decoder, native-client, HTTP-authentication and cryptography helpers are reported separately.

Runtime SHA-256: `edfbcf7756adf1f00953cce94c7d7741c69ccedffd55e2b2420bcf40ae36f7b6`. No fast-runtime or weight overlay was used. After their tests and canonical receipt audit completed, fourteen chains were stopped while the remaining mixed-multisig chain continued unchanged; this reduced unnecessary requests after the shared external Drand provider returned rate-limit responses. Alice funded disposable wallets and configured test subnet parameters through root calls. The three registration reserves were independently checked as 0.2 TAO.

This is envelope and dispatch parity against constrained fixtures; it does not mean every call succeeded or every business-state/input combination was enumerated. Deliberate permission and invalid-state rejections are part of the test.

The runtime binary was frozen before the chains launched and remained identical throughout. Long-running live SDK processes began at different points during the local repairs; their original timing is retained in the evidence. The full offline SDK suite and fresh multisig/delegate regressions exercised the final repaired SDK sources.

Some existing end-to-end fixtures assumed every submission consumed one nonce/signing generation and one fee. Default Shield now consumes two for shielded registration. Those assertions were corrected to inspect the selected route and canonical fee events. Sponsorship coverage was expanded to both explicit plain and shielded submissions for every protected mode. Superseded attempts remain in the evidence; their failures are not omitted or counted as passing. Accepted counts use unique test IDs, never repeated attempts.

The exact native Rust `Client::submit_shielded` remains unusable because it chooses a 64-block lifetime while the runtime accepts at most eight for Shield. All four protected modes were rejected before inclusion, leaving balance, nonce and authority unchanged. This defect also exists at the PR base; it is reported separately from introduced regressions. The existing native API also returns carrier outcome rather than independently resolving the decrypted operation. Python/CLI Shield uses a separate pipeline and passed its live checks. The existing Ethereum receipt fee-reporting discrepancy was not changed; actual balance debits were checked independently. These boundaries prevent a claim that every native SDK route works merely because the PR's runtime and Python/CLI tests pass.

Registration must finalize before a descriptor-derived address is publicly disclosed or funded. The accepted existing hostile-association risk is still present if that prerequisite is ignored; private registration through Shield and atomic descriptor-aware payment reduce exposure but cannot erase earlier disclosure. Ordinary Ethereum transaction signing retains secp256k1. Simulated Vault signers do not establish hardware-wallet or phone compatibility. This run does not prove absence of implementation errors, production saturation capacity, or reproducibility of a deployment image.

The PR still points to the same validated head/base. Its description retains the old 1.144-TAO MS registration amount and earlier validation counts. The current runtime and live tests use **0.2 TAO for all three registration reserves**; the description should be refreshed before release communication. No remote PR text was edited.

All validation processes are stopped. Shutdown verified every test RPC/P2P port and the temporary metadata endpoint closed, and a process scan found no remaining `node-subtensor` process. No commits or pushes were made. SDK repairs, regression tests and this evidence remain local for review.
