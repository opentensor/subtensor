The fresh code-4 hashed-SR live fixture reproduced this using the exact matching release-native dependency graph; funding and the prior finalized rotation succeeded, and offchain HTTP authentication passed. No signature or generation defect is implied by this pool rejection.

The same 64-versus-8 mismatch exists at merge-base `6a972693ae9580541225bd37696ac2fee26b8ae9`; it is an existing SDK availability problem, not an introduced ML-DSA regression. It nevertheless prevents successful validation of the exact native path on the current production runtime.
